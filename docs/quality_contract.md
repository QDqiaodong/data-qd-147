# 水质连续暴露数据仓（quality_cli）

独立的"水质连续暴露数据仓"数据应用。它把**可迟到更正的瞬时浓度观测**与**实验室校准
变更流**转为持久化的已知覆盖、超标暴露与告警区间。它不读取配给、交割、表位或费率
数据，与 v1 配给、`network_cli`、`billing_cli` 完全隔离（无共享文件、数据库或状态）。
一个 SQLite 文件就是一个配置冻结的仓。全部运行只用 Python 标准库，时间与浓度均为
精确有理数（`fractions.Fraction`），不采样、不浮点近似、不按单位展开。

```sh
python -m water_rights.quality_cli init   --source CONFIG    --db DB
python -m water_rights.quality_cli ingest --source CHANGES   --db DB
python -m water_rights.quality_cli report --db DB --start S --end E --output REPORT
```

业务错误（契约违规、最终态冲突、输出不安全等）一律退出 2，不触碰既有报告与仓；
成功时报告原子替换。输入与数据库不得相同，`init` 拒绝覆盖任何已存在文件（含符号
链接），报告不得覆盖数据库、输出符号链接拒绝。

## 仓配置（init --source）

受限 JSON，准确为 `{start, end, stations}`（拒绝未定义字段、重复键、非有限数值；
≤8 MB，规则与仓库 `common.read` 一致）。

- `start`、`end` 为整数 Unix 秒、UTC 午夜，满足
  `0 ≤ start < end ≤ 4102444800` 且 `end − start ≤ 31 × 86400`。
- `stations` 至多 30 项，每项准确 `{id, min_episode_seconds, analytes}`：
  - `id` 遵循既有 `ident` 规则（非空、去首尾空白、≤128 字符、无控制字符），站内唯一；
  - `min_episode_seconds` 为 1..10^6 整数；
  - `analytes` 为 1..5 项，每项准确 `{id, threshold, max_gap_seconds}`。污染物 `id`
    遵循 `ident` 且站内唯一；`threshold` 为非负有理数；`max_gap_seconds` 为
    1..10^6 整数。

**有理数表示**：输入统一为 `[n, d]`，`n` 为绝对值 ≤10^9 的整数，`d` 为
1..10^6 的整数，按数值处理（不要求既约）。拒绝布尔、浮点、额外字段、重复键。
输出一律既约 `[n, d]`、`d > 0`，零为 `[0, 1]`。

`init` 在全部校验通过前不落盘，失败不留半个数据库。

## 变更流（ingest --source）

UTF-8 JSONL，每行一个对象，最多 10000 行且 ≤8 MB；空行拒绝。每行准确
为 `{seq, kind, id, revision, deleted, payload}`：

- `seq`、`revision` 为正整数；`deleted` 为 JSON 布尔；`kind` 只取
  `observation` 或 `calibration`；`id` 遵循 `ident`。
- **实体键为 `(kind, id)`**：同一 id 的观测与校准是两个实体。
- 非删除观测 `payload` 准确 `{station, analyte, at, value}`：`at` 为仓时间闭区间
  `[start, end]` 内的**整数秒**，`value` 为非负有理数。
- 非删除校准 `payload` 准确 `{station, analyte, start, end, a, b}`：区间为仓内
  **正长度半开区间** `[start, end) ⊂ [start, end]`，端点整数秒，`a` 为正有理数，
  `b` 为有理数（可为负）。
- `station`/`analyte` 必须引用配置中的已知组合；删除事件的 `payload` 必须为 `null`。

### 修订与删除

- 实体首次 `revision = 1` 且必须非删除；之后每次恰加 1，不得跳号或重启。
- 首个 payload 确定的 `station`/`analyte` 此后不可改变；删除后**可**以同一组合
  恢复（删除事件自身不带 payload 标识，继承该实体的组合）。
- **每实体仅最高修订生效**。中间修订只作为历史事实保存，不参与物化。
- 批次**最终态**中，同站同污染物不得有同刻两条有效观测，有效校准区间不得重叠
  （可留空档）。批次**中间态**（如交换两条观测时刻）不做跨实体冲突判定。

### 断点、重放与原子性

- 仓持久保存**事件身份**（`(kind, id, revision)`）、**全部修订**原始 JSON 与
  **输入断点**（初始为 0）。
- 文件 `seq` 严格递增。`seq ≤ 断点` 的已提交事件，仅当完整解码事件按
  “对象键无关、数组顺序有关”的规范 JSON 表示完全一致时视为**重放**；同实体的
  新 revision 是不同事件，不会被当成重复。
- 新 `seq` 必须自当前断点 + 1 **连续**开始；缺口或倒退整批拒绝。
- 重放不触发 revision 跳号：断点与实体状态都不因纯重放而改变。
- 一次 `ingest` 将**有效修订、全部派生区间、断点**在同一 `BEGIN IMMEDIATE`
  事务内共同提交；任何失败（同 seq 异内容、seq 缺口、非法修订、最终态冲突、
  事件上限、物化异常）整体回滚，三者均保持旧值。
- 仓累计事件最多 50000 条，超过上限整批拒绝。
- 失败后恢复：修复输入并重新提交即可；已提交 seq 的重放不会重复生成暴露。

## 连续暴露物化

物化**只由当前有效事实生成**，结果持久化为 `report` 可直接查询的区间表；
`report` 不重新扫描原始变更流。

### 浓度与共同已知域

- 每污染物仅在**相邻有效观测之间**线性插值原始浓度；两观测间隔严格大于
  `max_gap_seconds`、缺少任一侧观测、或没有有效校准时，该处为**未知**；
  禁止外推、禁止按零填充。
- 校准在其半开区间 `[s, e)` 内使浓度为 `a × 插值浓度 + b`；校准后可以为负。
  多个校准不得重叠且各自独立生效，因此校准边界与观测边界共同切分线性片段。
- 只有站点**所有**配置污染物同时已知时，该时刻才属于站点**已知域**
  （各污染物已知集的交集）。

### 超标与积分

仅在已知域内，对每个污染物精确求解 `浓度 > threshold` 的时间集合（阈值交点可为
分数秒），再对站点取**并集**；同时，对每个污染物在已知域内精确积分
`max(浓度 − threshold, 0)`（单位：浓度·秒），分段按解析原函数计算。

- 多个污染物同时超标的秒数在并集中**只计一次**。
- 时刻、时长与积分全程精确有理数；无固定步长采样、无浮点近似。

### 告警

告警是**整个仓时间**内超标并集的极大正长度连通分量（闭包合并）：

- 仅单个端点的相等或同时切换**不拆段**；
- 两个超标段的**闭包相接**、且中间没有正长度安全段或未知段时**合并**；
- **正长度未知段必须拆段**；
- 段长 `≥ min_episode_seconds` 才保留，以**其全仓长度**判断资格；
- 告警跨 UTC 午夜保持**一个完整区间**，不得先分日或先裁剪查询再过滤。

### 变更驱动的重新物化

当观测更正移动时刻、撤销观测，或校准修订移动区间/改变系数/撤销恢复时，本次
ingest 依据最终有效事实**整体重建**已知覆盖、超标并集、逐污染物积分分段与完整
告警（先撤回全部旧派生区间，再写入新集合）。因此失效区间被移除，告警会正确
分裂或合并，而不是只追加新结果或只重算修订发生日。

## 报告（report --start S --end E --output REPORT）

要求 `S`、`E` 为仓内整数秒且 `S < E`，读取**同一已提交快照**，输出
`{schema_version: 1, kind: "quality-report", seq, warehouse, query, stations}`：

- `seq` 为该快照的已提交断点。
- 每站 `{station, min_episode_seconds, days, alerts}`。
- `days` 按站点与 **UTC 日期**给出查询范围内的 `known_seconds`、`unsafe_seconds`
  与逐污染物 `excess_integral`。日界按 UTC 切分但**不改变告警身份**；空日、
  全未知日亦给出零值。
- `alerts` 列出与查询有**正长度交集**的合格告警：原始 `start`/`end`/`length`
  与裁剪 `clipped_start`/`clipped_end`/`clipped_length`。资格用全仓长度判断，
  因此只查询一个跨午夜长告警的短尾仍返回该完整告警。
- 时间、时长、积分均输出既约 `[n, d]` 且 `d > 0`；零为 `[0, 1]`。站点按 id、
  日期按升序、告警按起始时刻确定排序。

## 为何这些区间表示同时保证覆盖、积分与跨日告警一致

1. **片段化（piecewise affine）表示**：把仓时间切成有限个片段，每个片段上
   `station 已知 ⟺ 每个污染物都落在某个 `[观测间段] ∩ [校准]` 内`，且每个
   污染物的校准后浓度在片段上是一个 `m·t + c`。共同已知域取各污染物覆盖区间
   集合的交集，与“所有污染物同时已知”的定义逐点等价，不依赖采样密度。
2. **精确积分**：`max(m·t + c − threshold, 0)` 在片段内至多一个零点，积分用
   解析原函数 `m·t²/2 + (c−threshold)·t` 在裁剪端点求差，全程 `Fraction`。
   `excess_integral` 因此对任意分数秒边界、任意校准系数都精确。
3. **闭包并集与告警一致**：超标集合用闭包 `[t_lo, t_hi]` 表示，仅当中间存在
   正长度安全段或未知段才不连通；因此“端点相等、同时切换不拆段”和“闭包相接
   合并”都由同一 `intervals_overlap_or_touch` 判定实现。告警在全仓范围生成、
   全仓长度过滤，日汇总和查询裁剪都在其**之后**进行，故跨午夜告警在日表、
   裁剪表与原始身份之间始终一致。
