# 取水许可证公告采集器数据契约（permit_collect）

离线"取水许可证公告采集器"。仅用 Python 标准库，把源站的分页公告、许可详情和
月配额 CSV 采集为一个可在无源站时离线复核的数据集。一个 SQLite 文件即一个绑定到
入口 URL 的采集器应用身份；原始响应正文（而非仅解析字段）与请求/最终 URL、
ETag、快照标识、SHA256 一并持久保存。本应用只处理公开许可的**声明配额**，不读取
也不改写配给交割、计费、水质仓。

```sh
python -m water_rights.permit_collect --index URL --state DB --output REPORT
python -m water_rights.permit_collect --index URL --state DB --output REPORT verify
```

业务错误、网络/解析/额度/来源/发布错误一律退出 2，并保留上一份已发布报告与全部
原始证据；只有成功才在 stdout 输出成功回执，回执含数据集身份 `dataset_id` 与
出口数 `outlets`，不含运行时间或随机值。

## 1. 源站快照契约

- 每次启动先重新验证首页，得到当前快照 `G`。首页探测不携带
  `X-Expected-Snapshot`（其职责是发现当前 G），但在本地有已验证首页时携带
  `If-None-Match`；未变化时源站答 304，变化时以新 G 的 200 应答。
- 首页之后的每个请求都携带 `X-Expected-Snapshot: G`。源站在同 G 内保证资源不可变；
  旧快照请求可返回 409/412，或在响应头给出不同的 `X-Permit-Snapshot`，二者都按
  快照冲突处理并中止本轮。
- 成功响应只接受 200 或 304，且二者都必须带**非空 ETag 与 X-Permit-Snapshot**。
  快照标识与 ETag 是非空、去空白、长度 ≤128、仅含可打印 ASCII 的不透明值。
- 其他 HTTP 错误、超时、连接失败或响应字段缺失均作为本轮失败，不做无限重试；
  每个请求有有限超时（默认 15 秒）。
- 304 仅在同时满足以下条件时才被采用：同一请求 URL、同一 G、本地存在 SHA256
  复核通过的原始字节。缓存字节损坏时删除损坏行并改为无条件重新下载，绝不使用
  损坏字节，也绝不用 304 凭空补出正文。
- 源站可在两次请求间把当前快照从 G 切换到 G2。首页复验发现 G2 后，本轮所有请求
  改钉 G2；任何旧 G 候选的派生行或未完成任务都不会混入 G2（见第 6 节）。

## 2. URL、重定向与抓取边界

- 入口必须是完整 `http`/`https` URL，以标准解析器处理；禁止 userinfo。
- origin 按 `(scheme, host 小写, 有效端口)` 比较，默认端口归一（http 80、
  https 443）；不对路径或查询串自行解码或重排。
- 重定向手工处理：每一跳在**发送下一个请求之前**检查目标与入口同
  scheme/host/有效端口且无 userinfo，跨源立即拒绝（因此外域服务器收到零请求），
  重定向至多 3 跳。
- 相对链接按**实际响应最终 URL** 解析；片段移除、查询串保留；不处理
  `base` 标签，不执行脚本。
- 只抓三类引用：首页的 `a#next` 分页链（每页至多一个，无 next 即结束）、
  `table#permits` 中的详情链接、详情页 `a#quota` 声明的 CSV。分页回边（再次指向
  已访问公告页）拒绝；详情或附件的重复引用只获取一次（去重），不视为分页回边。
- 硬限制：单 HTML/CSV ≤2 MB；本轮原始字节总量 ≤64 MB；公告页 ≤100、详情
  ≤2000、CSV ≤2000、公告逻辑数据行 ≤10000，任一超限本轮失败。

## 3. 公告 HTML 抽取

- 每页恰有一个 `table#permits`，含一个 `thead`（1..5 行 `th`）和一个 `tbody`
  （数据 `tr`/`td`），禁止嵌套表格；结构外的导航、广告一律忽略。
- 先按 `rowspan`/`colspan` 占位展开为逻辑矩形：`th` 允许 rowspan/colspan，
  `td` 只允许 rowspan；跨度为 1..50 的整数。单元格重叠、越过表尾、出现空洞或
  宽度不一致均拒绝。
- 叶标题取覆盖该列的最底层 `th` 文本，必须恰为"许可证号""持有人""详情"各一次；
  叶标题处不得用一格横跨多个必需列。文本先解 HTML 实体、拼接嵌套文本，再折叠
  Unicode 空白。
- 每个逻辑行的详情单元恰有一个带 `href` 的 `a`；输出值来自恢复后的对应逻辑单元，
  绝不来自固定物理列。数据 rowspan 可让许可号/持有人/详情链接被后续行继承；
  逻辑行号从 tbody 第一行起计 1。

## 4. 详情与 CSV 额度

- 详情页恰有一个 `dl#permit`，含恰四个 `dd`，分别以
  `data-field="permit_id|holder|outlet_id|annual_m3"` 标记；页面恰有一个
  `a#quota`（可在 dl 之外），带 `href` 与 64 位小写十六进制 `data-sha256`。
- 详情的许可号、持有人必须与对应公告行完全一致，否则本轮失败。
- CSV 为严格 UTF-8（可带 BOM）、遵循 RFC4180；表头必须准确为
  `outlet_id,month,licensed_m3`；禁止多余列、重复表头、空记录、额外出口。
- 每个出口恰有 1..12 月各一条，`month` 是 1..12 无前导零的整数文本；出口号必须
  与详情一致。CSV 记录号从表头后第一条**逻辑记录**起计 1，引号内换行不另加号。
- 额度文本只能是 `0` 或非零开头整数，可带 1..3 位小数；年度/月度额度上界
  10^9 m³。换算全部使用整数升（1 m³ = 1000 L），禁止浮点与静默四舍五入。
  十二个月整数升精确求和必须等于详情年度额度，否则本轮失败。
- CSV 原始字节的 SHA256 必须等于详情 `a#quota` 声明的 `data-sha256`。

## 5. 持久状态、候选表示与报告

SQLite 表（schema 标识 `permit-collector-v1`）：

- `meta`：schema、绑定的入口 URL、`published_run_id` 持久发布指针。
- `resources(request_url, snapshot)`：主键为请求 URL 与快照；保存
  `final_url`、`etag`、`sha256`、`kind` 与**原始响应字节 BLOB**。证据从不因某份
  报告发布而删除，因此旧快照证据保留，已发布数据始终可离线复核。
- `runs`：每轮一行，状态机为 `candidate → published → superseded`，失败轮记
  `failed`；发布时在同一事务写入规范 JSON 报告与 `dataset_id` 并移动指针。
- `run_outlets`：候选阶段持久化的已验证出口（规范化月配额与来源引用），使候选
  在中断后仍可检查，但它本身不构成已发布数据集。

报告按许可号、出口号、月份排序；每个出口给出整数升月配额、年度合计、快照 G、
来源引用列表与原始资源清单。每条来源引用含公告请求/最终 URL 与逻辑行号、详情
请求/最终 URL、CSV 请求/最终 URL 与逐月 CSV 记录号，以及三者的原始字节 SHA256，
可回到 `resources` 中的原始字节。清单至少记录请求 URL、最终 URL、G、ETag 与
原始 SHA256。

### 数据集身份编码规则

数据集身份是**报告核心内容**（完整报告去掉其自身 `dataset_id` 字段后）的规范
JSON 的 SHA256。规范编码固定为：UTF-8、键排序、分隔符 `,` 与 `:`、
`ensure_ascii=False`、`allow_nan=False`。因此身份字段本身不参与摘要，相同已验证
内容重跑必然产生同一份报告与同一身份；没有任何许可的合法空表也得到确定身份并
可发布。

## 6. 来源依赖失效、快照切换与报告/状态恢复协议

**候选表示为何能隔离未完成工作。** 一轮采集在一个 `BEGIN IMMEDIATE` 事务内把
已通过结构与身份校验的出口写入 `run_outlets`（状态 `candidate`），但
`published_run_id` 指针只在全部页面、详情、附件可达且交叉校验成功后，才在另一个
事务里原子切换。候选因此永远不是已发布数据集；新一轮 `begin_round` 先删除所有
`candidate/failed` 轮及其出口行，旧 G2 的派生行不可能被 G3 复用。

**来源依赖为何不能只按 URL 拼接。** `resources` 的主键含快照，缓存查询与 304
复用都以 `(request_url, G)` 为键；月配额只在抓取器返回同 G、对应最终 URL 且
`data-sha256` 与字节 SHA256 同时通过的附件后才产生。详情发生重定向时，附件相对
链接按新的最终 URL 解析；同一附件 URL 在 G3 返回不同字节时，其 ETag/SHA 不同，
会作为 G3 新证据落库，G2 的行随候选删除而清除，报告中只保留 G3 来源引用。

**三个发布边界崩溃后的恢复。** 数据库指针是唯一事实来源：

1. 候选已提交、指针未移动即退出：重启删除未完成候选并重新采集，从未发布过报告，
   不产生成功回执。
2. 指针已在 DB 移动、JSON 报告尚未替换即退出：重启先依据指针把库内规范报告经
   `common.save` 原子写回，再开始新一轮；不会出现"状态显示已发布、磁盘仍是旧
   报告"的成功回执。
3. JSON 已替换、回执未输出即退出：重启识别磁盘报告的身份与指针一致，恢复同一份
   确定报告，不重复出口、不重复配额。

显式 `verify` 在**完全离线**状态下重放全部证据：核对清单中每个 SHA 与 BLOB、
重新解析公告/详情/CSV、复算逐月整数升与年度守恒、校验记录号与数据集身份，任何
无法恢复核验的外部篡改都明确拒绝，绝不猜测成功。

## 7. 输出安全

- 输出路径不得等于 SQLite 文件或其 `-journal/-wal/-shm` 配套文件；拒绝符号链接
  输出。JSON 经 `common.save` 以同目录临时文件 + `os.replace` 原子替换。
- 发布失败不删除旧报告或旧证据；候选保留供重启恢复。源内容或额度校验失败时，
  部分候选绝不会被标记为已发布。

## 8. 自制演示站点与验收

`python -m water_rights.permit_demo --root fixtures/permit_site --snapshot G1`
启动标准库 `ThreadingHTTPServer`，实现快照头、ETag/304、412 与同源重定向，并可
带 `--foreign-port` 启动第二个外域服务器以核对跨源重定向零请求。测试覆盖：

- 调度：中断重启的 If-None-Match/304、缓存字节损坏后的无条件重下、首页换 G、
  异快照 412、分页回边、共享详情/附件去重、跨源重定向零请求、离线复核。
- 抽取：两层跨列/跨行表头、数据 rowspan、嵌套文本与实体、RFC4180 引号与 BOM、
  精确升换算、月份缺失/重复、年度不守恒、重复出口冲突、记录号回溯原始字节。
- 联动：G1 发布后 G2 抓到详情未抓附件即终止、源站再切 G3 同附件 URL 改配额，
  重启得到纯 G3 数据且无 G2 残留；详情重定向改变相对附件基址、合法 304 恢复、
  三个发布边界进程退出后的报告/身份/配额一致性。
